# 01 — 项目背景

## 数据来源

数据取自 Kaggle 上 Anton Kozyriev 发布的 [Game Recommendations on Steam](https://www.kaggle.com/datasets/antonkozyriev/game-recommendations-on-steam) 数据集。Steam 是全球最大的 PC 游戏发行平台，用户可以对已购买或体验过的游戏发表"推荐"或"不推荐"评价。该数据集抓取了 Steam 商店公开可访问的用户评价、游戏信息和用户档案数据，共计 **超过 4,100 万条推荐记录**。

### 数据文件

| 文件 | 核心字段 | 记录含义 |
|------|---------|---------|
| `games.csv` | 游戏 ID、标题、定价（美元）、评分、发布日期 | 每行是一款游戏的元信息 |
| `games_metadata.json` | 游戏 ID、描述文本、标签/类型数组 | 每行是一款游戏的富文本和分类元数据 |
| `users.csv` | 用户 ID、已购产品数、已发评论数 | 每行是一位匿名用户的公开档案 |
| `recommendations.csv` | 用户 ID、游戏 ID、是否推荐（0/1）、评价时间 | 每行是一条用户对游戏的推荐记录 |

数据的核心关系是 **用户-游戏-推荐** 的三元组：哪类用户、对什么特征的游戏、给出了正面还是负面的评价。

### 数据获取

使用 `kagglehub` 一行代码下载，自动缓存到本地：

```python
import kagglehub
path = kagglehub.dataset_download("antonkozyriev/game-recommendations-on-steam")
```

## 分析目标

以该数据集为蓝本，完成从原始数据到可落地结论的**完整数据科学流水线**：

```
背景分析 → 数据读取 → 清洗与预处理 → 探索性数据分析（EDA）
  → 可视化 → 特征工程 → sklearn 建模与超参数优化
  → 模型评估与对比 → 结果可视化 → 业务结论与应用建议
```

每个环节都由具体的研究问题驱动。

---

## 核心研究问题

### 问题 1 — 游戏生态画像：Steam 市场的结构性特征是什么？

**背景：** Steam 平台上的游戏高度异质——从 3A 大作到个人开发的独立游戏、从免费到数百美元的豪华版、从单类型到多类型混搭。了解这些维度上的分布特征，是后续一切分析的基础。

**可操作的分析点：**

- **价格分布：** 免费游戏 vs 付费游戏占比？付费游戏的价格集中在什么区间？是否存在"价格断层"（例如 $0-$10 和 $60-$70 两个高峰）？
- **评分分布：** Steam 评分是正面/总评的比例。评分是两极分化（大量差评和大量好评）还是集中于高分区？是否存在"高分偏差"（推荐率整体偏高）？
- **类型分布：** 从 `games_metadata.json` 的类型（tags/genres）字段统计什么类型最多？哪些类型组合最常出现？
- **发布日期趋势：** 游戏发布量随时间的变化趋势？是否在某些年份出现爆发（如 Steam Direct 上线后的 2017 年）？
- **头部集中度：** 少数游戏是否占据了绝大多数推荐量（长尾分布）？推荐量的 Power Law 指数是多少？

**预期产出：** 多张描述性统计图和结构化的生态画像总结。

---

### 问题 2 — 用户行为画像：谁在评价？活跃度分布如何？

**背景：** 用户的评价行为本身反映了其参与度。该数据集的用户表中没有人口统计信息（年龄/性别/地区），但提供了"已购产品数"和"已发评论数"两个关键行为指标。

**可操作的分析点：**

- **活跃度分布：** 大部分用户是"评价极少数游戏"的沉默用户，还是"什么都评"的重度用户？用直方图 + 分位数统计展示评论数和购买数的分布形态。
- **推荐偏好：** 用户整体推荐率是多少？不同活跃度的用户推荐倾向是否不同（活跃用户更严格 or 更宽松）？
- **极端用户识别：** 是否存在只发表好评或只发表差评的极端用户？这些用户的评价是否值得纳入建模？
- **购买-评论关系：** 已购产品数与已发评论数的相关性？是否存在"买很多但评很少"或"买很少但每条都评"的行为模式？

**预期产出：** 用户行为分层标准 + 可视化 + 数据清洗策略。

---

### 问题 3 — 推荐预测建模：能否基于用户和游戏特征预测推荐行为？

**背景：** 核心机器学习任务——二分类问题：给定一个用户和一款游戏，预测该用户是否会推荐该游戏。特征是用户画像和游戏画像的组合。这是一个典型的**混合推荐系统**思路：不仅依赖协同过滤（"相似用户喜欢相似游戏"），也利用内容特征（"这个游戏本身是什么样的"），可以部分缓解冷启动问题。

**可操作的分析点：**

- **数据集划分策略：** 按用户分组切分（`GroupShuffleSplit`）或按时间切分，防止数据泄漏
- **基线模型：** `DummyClassifier`（随机猜测、多数类预测）、简单规则（基于游戏口碑）
- **分类模型对比：** 逻辑回归 → 随机森林 → XGBoost
- **超参数优化：** `RandomizedSearchCV` 调优树模型参数
- **数据量策略：** 先采样 10-50 万条验证流程，再扩大

**预期产出：** 至少 3 个模型的对比评估表格 + 特征重要性排名 + 最优模型评估报告。

---

### 问题 4 — 特征对推荐行为的影响：什么因素驱动用户推荐？

**背景：** 预测准确率固然重要，但同样重要的是**理解为什么**。解读哪些特征对推荐行为影响最大，并将发现转化为可操作的业务建议。

**可操作的分析点：**

- **特征重要性分析：** 用户侧 vs 游戏侧特征哪个更重要？
- **单特征效应：** 部分依赖图（PDP）展示关键特征与推荐概率的关系
- **交互效应：** 是否存在特征交互？例如活跃度高的用户是否更看重评分？
- **冷启动分析：** 评论数极少的游戏或行为数据极少的用户，模型预测是否显著下降？

**预期产出：** 特征重要性可视化 + 部分依赖图 + 面向开发者和平台运营的可行动建议。

## 注意事项与技术挑战

1. **数据获取：** 使用 `kagglehub` 自动下载，首次需 `pip install kagglehub`
2. **内存管理：** `recommendations.csv` 超过 4,100 万行（约 4-5 GB），开发阶段使用 `nrows` 采样或 `chunksize` 分批
3. **JSON 解析：** `games_metadata.json` 的 tags/genres 以数组形式嵌套存储，需用 `MultiLabelBinarizer` 展平
4. **数据泄漏：** 不能用简单的 `train_test_split`，必须用 `GroupShuffleSplit` 按用户分组切分
5. **DLC 处理：** 附加内容是否纳入"游戏"分析需要判断
