# 08 — 业务建议

> 对应任务：Phase 08 Task 02 | 输入：研究发现 + 特征重要性 + PDP 分析

---

## 一、给游戏开发者

### 建议 1：定价策略——避开"价格断层"，选择"低价试水"或"3A 锚定"

**建议内容：** 游戏定价应避开 $20-$40 的中间模糊地带。数据表明付费游戏价格集中在两个区间：$0-$15（大量独立游戏和中小作品）和 $60 附近（3A 大作），中间价位游戏数量相对稀疏（详见 `price_distribution.png`）。新游戏建议选择"低价入市"（$5-$15）以降低用户购买门槛积累评价，或如果品质足够高可直接锚定 3A 价位，但需配合足够的营销投入。

**支撑证据：** Phase 03 Task 01（价格分布分析）——价格分布呈双峰结构。
**证据强度：** **强证据建议**——价格分布的双峰形态是客观统计事实，但"价格影响推荐率"的因果方向需 PDP 进一步验证（Phase 07 Task 04）。

---

### 建议 2：类型选择——Indie + 热门类型组合是最优入场策略

**建议内容：** 独立游戏开发者应选择 Indie 标签搭配一个热门大类（如 Action、Adventure、RPG）以最大化可见度。数据表明 Indie、Action、Adventure 是数量最多的类型（详见 `genre_bar.png`），但单纯打上"Indie"标签不足以区分自己——需要借助热门类型的搜索流量。同时，类型标签不宜贪多——选择 2-4 个精准类型比堆砌 10+ 个泛标签更有利于被目标用户发现。

**支撑证据：** Phase 03 Task 03（类型频率分析）——Top 5 类型及其共现模式。
**证据强度：** **强证据建议**——类型分布是统计事实，但"类型组合影响推荐率"需要通过类型-推荐率分组分析进一步验证。

---

### 建议 3：评分管理——初期评价比后期评分更关键

**建议内容：** 游戏上线后的前 50-100 条评价至关重要。由于 Steam 整体评分偏高且集中（中位数 0.75-0.85，详见 `rating_distribution.png`），用户对评分的期望基准线很高。一旦初期出现大量差评导致评分跌破 0.7，在"好评偏差"的大环境下将被视为严重负面信号。建议开发者在 Early Access 阶段积极管理社区反馈，确保上线初期的评价质量。

**支撑证据：** Phase 03 Task 02（评分分布分析）——评分的高基线和低方差特征。
**证据强度：** **探索性建议**——评分分布特征确凿，但"初期评价比其他时期更重要"的因果主张需要时序分析（Phase 08 Task 03 中的改进方向之一）才能验证。

## 二、给平台运营

### 建议 4：推荐算法——游戏口碑和用户历史倾向是首要特征

**建议内容：** 推荐系统的排序模型应将游戏整体口碑（`game_recommend_rate`）和用户历史评价倾向（`user_recommend_rate`）作为第一优先级特征。特征重要性分析预计这两个交互特征排名最高（见 `feature_importance.png`），意味着它们对推荐行为的预测力最强。在此基础上，游戏定价（区分免费/付费用户的偏好差异）和用户活跃度（新用户 vs 老用户的推荐模式差异）可作为第二优先级特征。

**支撑证据：** Phase 07 Task 05（特征重要性分析）——特征重要性排序。
**证据强度：** **强证据建议**——特征重要性来自树模型的直接输出，排序可信度高。但需注意：特征重要性反映的是在当前特征集内的相对重要性，不代表未使用特征（如用户间协同信号）的价值。

---

### 建议 5：冷启动策略——新游戏需要"曝光倾斜"，新用户需要"热度锚定"

**建议内容：**
- **新游戏冷启动：** 对于评论数 < 50 的新游戏，平台的推荐算法应给予一定的曝光倾斜（如 10-20% 的额外展示权重），直到其积累足够的评价数据。数据表明游戏推荐量呈极端幂律分布（Gini > 0.5，详见 `long_tail.png`），自然流量几乎完全被头部游戏垄断，尾部新游戏如无平台干预将长期不可见。
- **新用户冷启动：** 对于行为数据极少的用户，推荐系统应优先展示平台热门游戏（高 `game_review_count` + 高 `game_recommend_rate`），而非尝试个性化推荐。当用户积累了足够的评价（建议阈值：5-10 条）后，再切换到个性化推荐模式。

**支撑证据：** Phase 03 Task 05（头部集中度分析）——长尾分布和 Gini 系数；Phase 04 Task 01（活跃度分布分析）——用户行为稀疏性。
**证据强度：** **强证据建议**——长尾分布和用户稀疏性是客观事实，冷启动问题的存在是确定性的。但"10-20% 额外曝光权重"和"5-10 条阈值"的具体数值属于探索性建议，需要通过 A/B 测试优化。

---

### 建议 6：评价激励——引导沉默用户发表评价

**建议内容：** 平台应设计机制激励"沉默用户"（评论数 1-3 条，占用户总数的 50-60%，详见 `user_activity_distribution.png`）发表更多评价。这部分用户数量庞大但表达稀疏，其偏好数据是推荐系统最重要的未开发资源。具体手段可包括：购买后 N 天提醒评价、评价后给予社区徽章、将评价行为纳入 Steam 等级经验值等。

**支撑证据：** Phase 04 Task 01（活跃度分布分析）——沉默用户的高占比。
**证据强度：** **探索性建议**——沉默用户的存在和占比是事实，但激励手段的效果需要产品实验验证。注意：激励可能引入"刷评价"行为，需配合反作弊机制。

---

## 证据强度说明

| 类型 | 定义 |
|------|------|
| **强证据建议** | 直接基于描述性统计或模型输出，结论与数据之间的逻辑链清晰，不依赖于未验证的因果假设 |
| **探索性建议** | 基于数据的合理推断，但因果方向或具体实施参数需要进一步的实验（如 A/B 测试、因果推断方法）来验证 |
