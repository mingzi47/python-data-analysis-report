# 基于 antonkozyriev/game-recommendations-on-steam 数据集的数据分析

## 目标

完整数据分析案例（背景分析→数据读取→清洗等预处理→探索性分析EDA→可视化→特征处理→sklearn建模及优化→模型评估及分析→可视化→结果应用结论）

---

## 项目背景

### 一、数据来源

数据取自 Kaggle 上 Anton Kozyriev 发布的 [Game Recommendations on Steam](https://www.kaggle.com/datasets/antonkozyriev/game-recommendations-on-steam) 数据集。Steam 是全球最大的 PC 游戏发行平台，用户可以对已购买或体验过的游戏发表"推荐"或"不推荐"评价。该数据集抓取了 Steam 商店公开可访问的用户评价、游戏信息和用户档案数据，共计 **超过 4,100 万条推荐记录**。数据分三个文件组织：

| 文件 | 核心字段 | 记录含义 |
|------|---------|---------|
| `games.csv` | 游戏 ID、标题、定价（美元）、评分、发布日期 | 每行是一款游戏的元信息 |
| `games_metadata.json` | 游戏 ID、描述文本、标签/类型数组 | 每行是一款游戏的富文本和分类元数据 |
| `users.csv` | 用户 ID、已购产品数、已发评论数 | 每行是一位匿名用户的公开档案 |
| `recommendations.csv` | 用户 ID、游戏 ID、是否推荐（0/1）、评价时间 | 每行是一条用户对游戏的推荐记录 |

数据的核心关系是 **用户-游戏-推荐** 的三元组：哪类用户、对什么特征的游戏、给出了正面还是负面的评价。

### 二、分析目标

本项目的总体目标是：以该数据集为蓝本，完成从原始数据到可落地结论的**完整数据科学流水线**。流程覆盖：背景分析 → 数据读取 → 清洗与预处理 → 探索性数据分析（EDA） → 可视化 → 特征工程 → sklearn 建模与超参数优化 → 模型评估与对比 → 结果可视化 → 业务结论与应用建议。

不满足于"跑通流程"，而是要求每个环节都有具体的研究问题驱动。

### 三、核心研究问题

围绕数据集特性，提炼出以下四个递进的研究问题：

#### 问题 1 — 游戏生态画像：Steam 市场的结构性特征是什么？

**背景：** Steam 平台上的游戏高度异质——从 3A 大作到个人开发的独立游戏、从免费到数百美元的豪华版、从单类型到多类型混搭。了解这些维度上的分布特征，是后续一切分析的基础。

**可操作的分析点：**

- **价格分布：** 免费游戏 vs 付费游戏占比？付费游戏的价格集中在什么区间？是否存在"价格断层"（例如 $0-$10 和 $60-$70 两个高峰）？
- **评分分布：** Steam 评分是正面/总评的比例。评分是两极分化（大量差评和大量好评）还是集中于高分区？是否存在"高分偏差"（推荐率整体偏高）？
- **类型分布：** 从 `games_metadata.json` 的类型（tags/genres）字段统计什么类型最多？哪些类型组合最常出现？
- **发布日期趋势：** 游戏发布量随时间的变化趋势？是否在某些年份出现爆发（如 Steam Direct 上线后的 2017 年）？
- **头部集中度：** 少数游戏是否占据了绝大多数推荐量（长尾分布）？推荐量的 Power Law 指数是多少？

**预期产出：** 多张描述性统计图和 1 份结构化的生态画像总结。

---

#### 问题 2 — 用户行为画像：谁在评价？活跃度分布如何？

**背景：** 用户的评价行为本身反映了其参与度。该数据集的用户表中没有人口统计信息（年龄/性别/地区），但提供了"已购产品数"和"已发评论数"两个关键行为指标。理解用户的活跃度分布，有助于识别评价质量，也为后续建模的特征构造提供依据。

**可操作的分析点：**

- **活跃度分布：** 大部分用户是"评价极少数游戏"的沉默用户，还是"什么都评"的重度用户？用直方图 + 分位数统计展示评论数和购买数的分布形态。
- **推荐偏好：** 用户整体推荐率是多少？不同活跃度的用户推荐倾向是否不同（活跃用户更严格 or 更宽松）？
- **极端用户识别：** 是否存在只发表好评或只发表差评的极端用户？这些用户的评价是否值得纳入建模？
- **购买-评论关系：** 已购产品数与已发评论数的相关性？是否存在"买很多但评很少"或"买很少但每条都评"的行为模式？

**预期产出：** 用户行为分层标准 + 可视化 + 数据清洗策略（例如是否剔除极端用户）。

---

#### 问题 3 — 推荐预测建模：能否基于用户和游戏特征预测推荐行为？

**背景：** 这是核心的机器学习任务——二分类问题：给定一个用户和一款游戏，预测该用户是否会推荐该游戏。特征是用户画像（购买数、评论数、历史推荐率）和游戏画像（价格、评分、类型、发布时间）的组合。

这是一个典型的**混合推荐系统**思路：不仅依赖协同过滤（"相似用户喜欢相似游戏"），也利用内容特征（"这个游戏本身是什么样的"），可以部分缓解冷启动问题。

**可操作的分析点：**

- **数据集划分策略：** 由于是用户-游戏交互数据，如果随机切分会导致**数据泄漏**（同一用户的历史行为同时在训练集和测试集中）。需要考虑按用户或按时间划分。
- **基线模型：** 先跑一个最朴素的模型（如总是预测"推荐"，或者基于全局推荐率的随机猜测）作为性能底线。
- **分类模型对比：** 逻辑回归（线性基准）→ 随机森林（非线性、可解释特征重要性）→ XGBoost/LightGBM（通常最强的表格数据分类器）。
- **超参数优化：** 使用 GridSearchCV 或 RandomizedSearchCV 对树模型的关键参数（n_estimators, max_depth, learning_rate）进行调优。
- **数据量策略：** 4,100 万条全量难以在单机上训练，需要先随机采样（如 5-10 万条）验证流程可行性，再逐步扩大。

**预期产出：** 至少 3 个模型的对比评估表格 + 特征重要性排名 + 最优模型的详细评估报告。

---

#### 问题 4 — 特征对推荐行为的影响：什么因素驱动用户推荐一款游戏？

**背景：** 预测准确率固然重要，但同样重要的是**理解为什么**。结合问题 3 的模型输出，解读哪些特征对推荐行为影响最大，并将这些发现转化为可操作的业务建议（例如：开发者应该把资源投向定价还是类型选择？平台应该如何调整推荐算法？）。

**可操作的分析点：**

- **特征重要性分析：** 从随机森林/XGBoost 提取 feature importance，排名前 10 的特征是什么？是用户侧特征重要还是游戏侧特征重要？
- **单特征效应：** 利用部分依赖图（Partial Dependence Plot, PDP）展示关键特征与推荐概率的关系——例如：价格越高推荐率越低？评分越高的游戏推荐率自然越高？
- **交互效应：** 是否存在特征交互？例如"活跃度高的用户对高评分游戏的推荐率更高"（即用户经验会调节评分的影响力）。
- **冷启动分析：** 当游戏评论数极少（<10 条）或用户行为数据极少（<5 条评论）时，模型预测的置信度和准确率是否会显著下降？

**预期产出：** 特征重要性可视化 + 部分依赖图 + 2-3 条面向游戏开发者和平台运营的**可行动建议**。

### 四、注意事项与技术挑战

1. **数据获取：** 数据集托管在 Kaggle，使用 `kagglehub` Python 库一行代码下载。首次使用需 `pip install kagglehub`，运行时 `kagglehub.dataset_download("antonkozyriev/game-recommendations-on-steam")` 会自动下载并缓存到本地，返回缓存路径。
2. **内存管理：** `recommendations.csv` 超过 4,100 万行，全量加载可能超出普通机器内存（约需 4-5 GB），建议开发阶段使用 `pandas` 的 `chunksize` 参数或随机采样（`nrows`）加载一个子集。
3. **数据清洗注意：** `games_metadata.json` 是非表格化的嵌套 JSON 文件，其中标签/类型（tags/genres）以数组形式存储，需要解析展开。DLC 和附加内容是否应纳入"游戏"分析需要判断。
4. **数据泄漏风险：** 切分训练/测试集时，不能简单地 `train_test_split`，否则同一个用户的多条记录会同时出现在训练和测试集中，导致过高的虚假评估指标。应使用按用户 ID 分组切分或时间切分。

## 数据分析方法与过程

### 阶段 1 — 数据读取

**目标：** 将三个 CSV 文件和一个 JSON 文件加载到 Python 环境中，建立初步的数据认知。

**方法：**

| 文件 | 读取方式 | 说明 |
|------|---------|------|
| `games.csv` | `pd.read_csv()` 全量读取 | 游戏数量有限（预计数万-十余万），可直接全量加载 |
| `users.csv` | `pd.read_csv()` 全量读取 | 用户数量较大但可一次性加载 |
| `recommendations.csv` | `pd.read_csv(nrows=N)` 采样读取 | 4,100 万行过大，开发阶段采样 10-50 万条；最终分析可考虑 `chunksize` 分批或 Dask |
| `games_metadata.json` | `json.load()` 逐行解析后转 DataFrame | 每行是独立 JSON 对象，需用列表推导式提取 `app_id` + `tags`/`genres` 列表 |

**操作步骤：**
1. 使用 `kagglehub.dataset_download("antonkozyriev/game-recommendations-on-steam")` 下载数据集，返回缓存路径 `path`
2. `pd.read_csv(path + "/games.csv")` 等加载各文件，打印 `shape`、`info()`、`head()` 建立基本认知
3. 读取 `path + "/games_metadata.json"`，提取 `app_id`、`tags`、`genres` 三个字段，展平为 DataFrame
4. 检查各文件的主键唯一性：`games.csv` 的 `app_id`、`users.csv` 的 `user_id`、`recommendations.csv` 的 `(user_id, app_id)` 组合

---

### 阶段 2 — 数据清洗与预处理

**目标：** 处理缺失值、异常值、数据类型转换、重复记录，使数据满足后续分析和建模要求。

**方法：**

**2.1 缺失值处理**

| 检查项 | 方法 | 处理策略 |
|--------|------|---------|
| 缺失值统计 | `df.isnull().sum() / len(df)` 计算每列缺失比例 | 先统计再决策 |
| 游戏标题缺失 | — | 删除该行（无法标识） |
| 游戏评分缺失 | — | 用中位数填充（评分可能有偏，中位数比均值更稳健） |
| 发布日期缺失 | — | 标记为 "unknown" 或填充数据集中位数年份 |
| 用户行为数据缺失 | — | 若购买数/评论数缺失，填充为 0（保守假设：无公开记录即无行为） |
| 推荐记录中的缺失 | — | 若 `is_recommended` 缺失，删除该行（目标变量不可推测） |

**2.2 数据类型转换**

- `date` 列 → `pd.to_datetime()`，提取 `year`、`month` 供后续特征工程使用
- `price` 列 → 确保为 float，检查是否有非数字字符（如 "Free" 文本）
- `is_recommended` → 转为 `int`（0/1）
- `tags` / `genres` → 从 JSON 数组转为 Python list，再用 MultiLabelBinarizer 展开为多列二值特征

**2.3 异常值检测**

- **价格异常：** 使用 IQR 方法检测，结合业务判断。例如价格 > $500 可能是特殊版本（Soundtrack/ Collector's Edition），不直接删除但标记
- **用户活跃度异常：** 评论数 > 已购产品数 是逻辑异常，标记并考虑排除
- **评分异常：** Steam 评分理论范围 [0, 1]（推荐率），检查是否有超出范围的记录

**2.4 重复与冗余**

- `recommendations.csv` 中同一 `(user_id, app_id)` 是否有多条记录（可能是多次修改评价），保留最新一条
- `games.csv` 中是否有相同的 `app_id` 反复出现，若有则保留一条

### 阶段 3 — 探索性数据分析（EDA）

**目标：** 通过统计描述和可视化回答核心研究问题 1 和 2（游戏生态画像 & 用户行为画像）。

**方法：**

**3.1 单变量分析 — 游戏维度**

| 分析项 | 统计方法 | 可视化方法 |
|--------|---------|-----------|
| 价格分布 | `describe()` + 分位数 + 偏度/峰度 | 直方图 + KDE（log 变换后的 x 轴）；饼图展示免费 vs 付费占比 |
| 评分分布 | `describe()` + 分位数 | 直方图 + KDE；叠加竖线标注均值和中位数 |
| 类型频率 | `value_counts()` 统计每个 tag/genre 的游戏数 | 横向条形图（Top 20 类型） |
| 发布时间趋势 | `groupby('year').size()` | 折线图（年度游戏发布数） |

**3.1 单变量分析 — 用户维度**

| 分析项 | 统计方法 | 可视化方法 |
|--------|---------|-----------|
| 评论数分布 | `describe(percentiles=[.25, .5, .75, .9, .95, .99])` | 直方图（log-log 坐标，展示长尾） |
| 购买数分布 | 同上 | 直方图（log-log 坐标） |
| 推荐率分布 | 每位用户的 `is_recommended.mean()` | 直方图，标注 0.5 和总体均值 |

**3.2 双变量与多变量分析**

| 分析项 | 方法 | 可视化 |
|--------|------|--------|
| 价格 vs 评分 | Spearman 秩相关系数（价格不满足正态） | 散点图 + LOWESS 平滑曲线 |
| 类型 vs 评分 | 按类型分组计算平均评分 | 分组柱状图 |
| 发布时间 vs 评分 | 按年份分组计算平均评分 | 折线图 |
| 用户活跃度 vs 推荐倾向 | 按活跃度分层（低/中/高），计算各层推荐率 | 箱线图 |
| 头部集中度 | 计算 Gini 系数 + 绘制 Lorenz 曲线；按游戏统计推荐量，降序排列计算累计占比 | 长尾分布曲线（log-log） |

**3.3 关键指标计算**

- Gini 系数（衡量游戏推荐量的不平等程度）
- 用户平均推荐率
- 付费游戏 vs 免费游戏的平均推荐率差异（t 检验或 Mann-Whitney U）
- 各年份游戏发布量的 CAGR（复合年增长率）

### 阶段 5 — 特征工程

**目标：** 从原始字段构造可用于 sklearn 模型的特征矩阵 X 和目标向量 y。

**5.1 目标变量**
- `y = recommendations.is_recommended`（0 或 1，二分类）

**5.2 特征构造**

按来源分三类：

**（A）游戏侧特征（来自 `games.csv` + `games_metadata.json`）**

| 原始字段 | 特征构造方式 | 输出特征 |
|---------|-------------|---------|
| `price` | 直接使用 + 二值化 | `price`, `is_free`（price==0） |
| `rating` | 直接使用（0-1 连续值） | `rating` |
| `date` | 提取年份，距今的年数 | `release_year`, `years_since_release` |
| `tags` / `genres` | MultiLabelBinarizer 展开 | 每个热门类型一列（0/1），选取出现频率 > 1% 的类型 |
| — | 类型数量 | `num_tags`, `num_genres` |

**（B）用户侧特征（来自 `users.csv`）**

| 原始字段 | 特征构造方式 | 输出特征 |
|---------|-------------|---------|
| `products` | 直接使用 | `user_products_count` |
| `reviews` | 直接使用 | `user_reviews_count` |
| — | 衍生特征 | `review_ratio = reviews / products`（购买后评价率） |

**（C）交互特征（来自 `recommendations.csv` 聚合）**

| 特征 | 构造方式 | 含义 |
|------|---------|------|
| `game_review_count` | 按 `app_id` 统计推荐总条数 | 游戏热度 |
| `game_recommend_rate` | 按 `app_id` 统计 `is_recommended.mean()` | 游戏整体口碑 |
| `user_recommend_rate` | 按 `user_id` 统计 `is_recommended.mean()` | 用户整体评价倾向（宽松/严格） |
| `user_review_count` | 按 `user_id` 统计条数 | 用户在该数据集中的活跃度 |

> **注意：** 交互特征的构造必须仅在训练集上计算，然后映射到测试集，避免数据泄漏。或者，使用时间切分（按 `date` 字段）确保聚合只用"历史"数据。

**5.3 特征处理流水线**

使用 `sklearn.pipeline.Pipeline` 和 `ColumnTransformer` 构建可复用的处理流水线：

```
ColumnTransformer:
├── 数值特征（price, rating, user_products_count, ...）
│   └── StandardScaler（标准化，均值为 0 方差为 1）
├── 二值特征（is_free, 各类型 0/1 列）
│   └── passthrough（无需处理）
└── 类别特征（release_year）
    └── OneHotEncoder（如年份数较多）
```

**5.4 特征选择（可选）**

- 若特征数过多（> 50），使用 `SelectKBest`（mutual information）或基于树模型的特征重要性进行筛选
- 移除方差接近 0 的特征（`VarianceThreshold`）

### 阶段 6 — 建模与优化

**目标：** 训练并对比多个分类模型，选出最优模型并调参。

**6.1 数据集划分**

采用**按用户分组切分**（Group-based split）防止数据泄漏：

```python
from sklearn.model_selection import GroupShuffleSplit

gss = GroupShuffleSplit(n_splits=1, test_size=0.2, random_state=42)
train_idx, test_idx = next(gss.split(X, y, groups=recommendations['user_id']))
```

- 训练集 : 测试集 = 80% : 20%
- 组标识 = `user_id`，确保同一用户的所有评价只在一个集合中
- 若数据量大，可先用 10-20% 采样进行模型选择和调参，确定最佳方案后再用全量数据训练最终模型

**6.2 基线模型**

| 基线 | 方法 | 意义 |
|------|------|------|
| 随机猜测 | `DummyClassifier(strategy='uniform')` | 理论下限（50%） |
| 多数类预测 | `DummyClassifier(strategy='most_frequent')` | 总是预测"推荐"的准确率 |
| 简单规则 | 若 `game_recommend_rate > 0.5` 则预测推荐 | 纯基于游戏口碑的朴素规则 |

所有后续模型必须**显著优于**这三个基线，才有实际价值。

**6.3 候选模型**

| 模型 | 角色 | 关键参数 |
|------|------|---------|
| **逻辑回归** (`LogisticRegression`) | 线性基准，可解释性强 | `C`（正则化强度）、`penalty`、`solver` |
| **随机森林** (`RandomForestClassifier`) | 非线性，特征重要性可解释 | `n_estimators`、`max_depth`、`min_samples_split` |
| **XGBoost** (`XGBClassifier`) | 梯度提升，通常性能最强 | `n_estimators`、`max_depth`、`learning_rate`、`subsample` |

**6.4 超参数优化**

使用 `RandomizedSearchCV`（比 GridSearchCV 更高效）：

- 每个模型选 3-4 个关键参数
- `n_iter=20`、`cv=3`（3 折交叉验证，减少计算量）
- 评估指标：`scoring='roc_auc'`（推荐/不推荐可能存在类别不平衡，AUC 比准确率更稳健）

**6.5 训练注意事项**

- XGBoost 支持早停（`early_stopping_rounds`），需要设置 `eval_set`
- 随机森林和 XGBoost 可设置 `class_weight='balanced'` 处理类别不平衡
- 记录每个模型的训练时间，作为模型选择的辅助参考
